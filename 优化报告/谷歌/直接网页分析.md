这是一个非常棒的部署计划。树莓派 5 配合 NVMe 和 16GB 内存是运行 Immich 的理想硬件，而 ZFS 将为你提供极高的数据可靠性。

基于你提供的 2026 年 2 月的时间点（假设 Immich 已迭代至 2.5.5 版本）以及树莓派 5 的硬件特性，我为你设计了最佳的 ZFS 存储布局和 Docker 配置方案。

### 第一步：ZFS 存储池规划与优化 (核心步骤)

在 `appdata` 下，我们需要为 Immich 的不同组件（数据库、媒体库、模型缓存）创建独立的数据集（Dataset），因为它们的 I/O 特性截然不同。

#### 1. ZFS 优化逻辑

* **Postgres 数据库**: 需要极低的随机写入延迟。
* `recordsize=16k`: **最关键参数**。匹配 Postgres 的默认页大小，防止“写放大”效应，大幅提升性能。
* `primarycache=metadata`: 树莓派只有 16GB 内存，数据库本身有缓存，ZFS 就不需要再缓存数据内容了，避免双重缓存浪费内存。
* `logbias=latency`: 优化数据库事务提交速度。


* **Library (照片/视频)**: 主要是大文件顺序读写。
* `recordsize=1M`: 提高大文件读取效率，减少元数据碎片。


* **全局设置**:
* `xattr=sa` & `acltype=posixacl`: **Docker 必须项**。这对 overlayfs 性能至关重要。
* `atime=off`: 减少不必要的写入（保护 SSD 寿命）。
* `compression=zstd`: NVMe 性能足够，Zstd 提供很好的压缩比和速度平衡。



#### 2. ZFS 创建命令

请在树莓派终端依次执行以下命令：

```bash
# 1. 设置根数据集的通用高性能参数 (会被子数据集继承)
sudo zfs set compression=zstd appdata
sudo zfs set atime=off appdata
sudo zfs set xattr=sa appdata
sudo zfs set acltype=posixacl appdata

# 2. 创建 Immich 父数据集
sudo zfs create appdata/immich

# 3. 创建 数据库 数据集 (针对 Postgres 优化)
sudo zfs create -o recordsize=16k -o primarycache=metadata -o logbias=latency appdata/immich/postgres

# 4. 创建 媒体库 数据集 (针对大文件优化)
sudo zfs create -o recordsize=1M appdata/immich/library

# 5. 创建 模型缓存 数据集 (标准设置)
sudo zfs create appdata/immich/model-cache

# 6. 验证创建结果
zfs list -r appdata/immich
zfs get recordsize,primarycache,compression appdata/immich/postgres

```

### 第二步：配置环境文件 (.env)

根据你的 ZFS 路径修改了配置。请在部署目录下创建 `.env` 文件。

**文件：`.env**`

```bash
# Immich 运行环境配置
# 文档参考: https://docs.immich.app/install/environment-variables

###################################################################################
# 核心路径配置 (映射到刚才创建的 ZFS 数据集)
###################################################################################

# 上传文件存储位置 -> 对应 appdata/immich/library
UPLOAD_LOCATION=/appdata/immich/library

# 数据库文件存储位置 -> 对应 appdata/immich/postgres
DB_DATA_LOCATION=/appdata/immich/postgres

# 模型缓存位置 -> 对应 appdata/immich/model-cache
# (注意：我将在 docker-compose.yml 中添加此变量的引用，原版yml这里是写死的volume)
MODEL_CACHE_LOCATION=/appdata/immich/model-cache

###################################################################################
# 版本与时区
###################################################################################

# Immich 版本，锁定为你指定的 2.5.5
IMMICH_VERSION=v2.5.5

# 时区设置 (建议设置，方便日志排查)
TZ=Asia/Shanghai

###################################################################################
# 数据库凭证 (建议修改 DB_PASSWORD)
###################################################################################

DB_PASSWORD=postgres
DB_USERNAME=postgres
DB_DATABASE_NAME=immich

###################################################################################
# 可选硬件加速配置 (树莓派 5 专用)
###################################################################################
# 树莓派 5 没有 NVENC，主要靠 CPU 或将来支持的 NPU。
# 机器学习通常不需要改这里，默认会自动使用 CPU/Neon 指令集。

```

### 第三步：Docker Compose 配置 (docker-compose.yml)

我对官方模板进行了以下关键修改以适配你的环境：

1. **机器学习镜像标签**: 添加了 `-armnn` 后缀（如果官方提供），这通常能利用 ARM 的神经网络加速特性。如果没有特定 tag，使用默认的也可以，它会自动回退到 CPU。考虑到稳定性，我们先用标准 tag。
2. **Volume 映射**: 将 `model-cache` 从 Docker 卷修改为直接挂载 ZFS 路径，保证所有数据都在 ZFS 控制下。
3. **重启策略**: 保持 `always`。

**文件：`docker-compose.yml**`

```yaml
name: immich

services:
  immich-server:
    container_name: immich_server
    image: ghcr.io/immich-app/immich-server:${IMMICH_VERSION:-release}
    volumes:
      # 映射 ZFS 媒体库
      - ${UPLOAD_LOCATION}:/usr/src/app/upload
      - /etc/localtime:/etc/localtime:ro
    env_file:
      - .env
    ports:
      - '2283:2283'
    depends_on:
      - redis
      - database
    restart: always
    healthcheck:
      disable: false

  immich-machine-learning:
    container_name: immich_machine_learning
    # 树莓派 5 架构为 arm64。通常标准镜像已包含 ARM 支持。
    image: ghcr.io/immich-app/immich-machine-learning:${IMMICH_VERSION:-release}
    volumes:
      # 修改为 ZFS 路径挂载，而非 Docker 内部 Volume
      - ${MODEL_CACHE_LOCATION}:/cache
    env_file:
      - .env
    restart: always
    healthcheck:
      disable: false

  redis:
    container_name: immich_redis
    image: docker.io/valkey/valkey:9@sha256:546304417feac0874c3dd576e0952c6bb8f06bb4093ea0c9ca303c73cf458f63
    healthcheck:
      test: redis-cli ping || exit 1
    restart: always

  database:
    container_name: immich_postgres
    # 保持官方锁定的 hash 版本以确保稳定
    image: ghcr.io/immich-app/postgres:14-vectorchord0.4.3-pgvectors0.2.0@sha256:bcf63357191b76a916ae5eb93464d65c07511da41e3bf7a8416db519b40b1c23
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_USER: ${DB_USERNAME}
      POSTGRES_DB: ${DB_DATABASE_NAME}
      POSTGRES_INITDB_ARGS: '--data-checksums'
    volumes:
      # 映射 ZFS 数据库数据集
      - ${DB_DATA_LOCATION}:/var/lib/postgresql/data
    # 树莓派内存优化: 共享内存
    shm_size: 128mb
    restart: always
    healthcheck:
      disable: false

```

### 第四步：启动与检查

1. **创建目录**: 确保你的部署目录里只有 `.env` 和 `docker-compose.yml`。
2. **启动**:
```bash

```


3. **检查日志**:
```bash

```


* 重点观察 `database` 是否成功初始化（因为我们挂载了新的 ZFS 路径）。
* 观察 `immich-server` 是否成功连接数据库。



### 特别提示：关于树莓派 5 的硬件转码

树莓派 5 移除了之前版本中的 H.264 硬件编码器，主要依赖强大的 CPU 进行软件编码。Immich 默认配置下使用 CPU 转码在 Pi 5 上性能是可以接受的（特别是你现在的 ZFS 优化减少了 I/O 等待）。

如果后续发现视频生成缩略图过慢，不要急着改配置，因为 Pi 5 目前并没有成熟的 Docker 内 NVENC/VAAPI 替代方案，保持默认的软件转码是最稳定的选择。
